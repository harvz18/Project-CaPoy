# Phase 7 — Revenue Analytics, Admin UI, and Notifications

## Result

Authorized administrators and superadministrators now have time-filtered, Firestore-backed TASKLINK service-fee analytics. The existing identity-verification, payment-review, and superadmin configuration flows were preserved.

## Financial accounting rules

- Only service-fee records with a verified collection event contribute to gross collected revenue.
- Worker wages, pending fees, submitted receipts, rejected submissions, and unverified screenshots are never counted as collected revenue.
- Gross verified collections, recorded refunds or credits, and net retained revenue are shown separately.
- Fee obligation totals remain separate from collected revenue, so outstanding amounts cannot be mistaken for revenue.
- Analytics deduplicate source records by document ID, preventing duplicate approvals from being counted twice.

## Analytics delivered

- Added 1-day, 3-day, 1-week, and 1-month Manila-time filters while retaining compatible existing range support.
- Added verified revenue, pending fees, submitted-for-review fees, rejected fees, outstanding obligations, and fee-bearing task counts.
- Added verified revenue by day, month, and task category.
- Extended the existing mobile admin analytics screen with compact financial totals and category/month breakdowns.
- Extended the existing superadmin portal Revenue page with the same trusted, time-filtered aggregates; no portal redesign was made.
- All figures are generated by the administrator-authorized `getAdminAnalytics` Function from actual `platformFees` records.

## Payment review and configuration

- Existing compact TASKLINK service-fee review stays alongside identity verification and normal GCash worker-payment review.
- Existing superadmin GCash destination, service-fee rate, and instructions controls remain unchanged and continue to write audit-log entries.

## Notifications

The existing notification system is reused; no paid notification provider was added.

- Worker selection: preserved.
- Service-fee payable and posting restriction applied: added to both trusted acceptance paths.
- Fee submitted, verified, and rejected: preserved; verified notices now explicitly state that the posting restriction was removed.
- GCash worker payment awaiting confirmation: preserved.
- Cash payment awaiting confirmation, PIN ready (without the PIN), and mutual confirmation: mirrored in the callable path to match the existing Admin API path.
- Task Finished: preserved by the existing workflow notification path.
