# UX review checklist

- [ ] Route, audience, entry, primary task, success, cancel/back, and deep-link behavior recorded.
- [ ] Meaningful heading and obvious primary action.
- [ ] Loading, empty, error, offline, unauthorized, refreshing, success states considered as relevant.
- [ ] Back, close, active navigation, and role fallback are predictable.
- [ ] Inputs have labels, correct keyboard/autocomplete, validation, retained values, and actionable errors.
- [ ] Pending actions prevent duplicates and provide visible progress.
- [ ] Destructive actions have specific confirmation and safe cancellation.
- [ ] Interactive controls have accessible names/roles and comfortable hit regions.
- [ ] State is not communicated by color alone.
- [ ] Text scaling, long content, narrow viewport, safe areas, and keyboard do not hide content/actions.
- [ ] Reduced motion and web keyboard focus are respected.
- [ ] Fees, permissions, statuses, deadlines, and outcomes are transparent.
- [ ] Existing API, authentication, data, and business rules remain unchanged.
- [ ] Test evidence and untested/blocked checks are recorded honestly.
