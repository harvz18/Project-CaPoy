# Visual Reference Analysis

Use the two supplied mobile screenshots as the highest-priority visual source. The earlier pastel liquid-glass direction is secondary and must not override this dark system.

## Shared Identity

- Deep navy/ocean-blue canvas continuing behind cards, headers, and floating navigation.
- A few broad, blurred cyan and teal light fields create depth without visible decorative clutter.
- Semi-transparent blue-tinted panels with thin pale-cyan borders and soft upper-edge reflections.
- White primary text, pale blue-gray supporting text, cyan outline icons, and emerald/teal focal actions.
- Rounded mobile-first geometry, balanced vertical rhythm, generous padding, and floating elevated chrome.
- Strong hierarchy: most surfaces stay quiet; only the hero, active route, primary action, or featured summary receives pronounced illumination.

## Dashboard Reference

- Minimal header over the atmospheric background.
- One highlighted welcome/summary panel.
- Responsive two-column statistic cards at mobile widths when content fits.
- Scannable task/job cards with clear metadata and actions.
- Floating glass bottom navigation with a gradient active pill.

## Profile Reference

- Large frosted profile panel and avatar with a controlled cyan rim.
- Small glass badges, three-column statistics where width allows, and dark transparent form fields.
- Thin reflective card borders and subtle cyan light concentrated near selected edges.
- The same floating navigation and background atmosphere as the dashboard.

## Fidelity Boundaries

- Use the application's actual content, routes, statistics, icons, and information architecture.
- Do not copy browser chrome, status bars, Android system navigation, compression artifacts, or sample personal data.
- Adapt the hierarchy to each real workflow instead of forcing every page into the dashboard/profile composition.
- On desktop, use appropriate sidebar/top navigation and bounded multi-column layouts; do not merely stretch the mobile screenshot.
